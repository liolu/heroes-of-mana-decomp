## 3. Plan pour tout matcher, par ordre de rendement (octets / heure)

### A. Les géants des overlays de scène (ov007–ov032) — 22 % du code en ~64 fonctions
`func_ov007_020d09f4` (12.4 KB), `ov014_020d08e8` (11.5 KB), `ov010_020d096c`, `ov032_020d4524`, `ov026_020d0fa0`,
`ov021_020d08b8`, `ov015_020d06a0`, `ov019_020d062c`, `ov009_020d0704`, `ov030_020d080c`, … : même position
(~0x020d0xxx, juste après l'init déjà matchée en session 7), même forme (`call/ldm/loop`) → **une seule famille**
(script de scène / état d'événement par overlay).
1. Générer un draft m2c avec plus de temps/mémoire (`--stack-structs`, pas de timeout) ou découper par blocs de base.
2. En matcher **une** à la main (la plus petite de la famille, ~3–5 KB) : switch d'état géant → écrire avec `default:` à la fin (swdefault), struct de scène typée (pas de M2C_FIELD), profil 1.2/sp3 et -O2 testés avec optsweep.
3. `hunt.py sibs` sur toute la famille → l'ordre des appels/offsets se transplante.
Gain potentiel : **+15–20 % de code** pour quelques sessions. C'est de loin le meilleur investissement.

### B. Débloquer les 1327 fonctions `-profile` (27 %)
Blocage connu : l'enregistrement `.data` du nom fait len+1 octets, objdiff veut une taille ×4 → seul 51/238 passent.
Pistes à tester dans l'ordre :
1. Émettre le nom dans un tableau explicite `static const char rec[16] = "CutFromPartner";` (taille forcée = arrondie) au lieu de laisser mwcc générer la chaîne.
2. Sinon, mettre le padding dans le fichier de gap suivant (étendre la plage `.data` du gap, pas celle du TU) et laisser objdiff comparer un `.data` non arrondi.
3. Sinon, patcher verify pour tolérer la queue de padding nulle (en le documentant : ROM identique de toute façon).
Une fois débloqué : pipeline profhook → profmap → fixrun avec `AUTO_EXTRA_PROFILES='1.2/sp3 -profile,2.0/sp1p5 -profile'`
sur toutes ces fonctions (session 8 l'a déjà prouvé sur 51).

### C. Les 2346 "compile" (47 %) — réparer m2c en masse, pas à la main
- `M2C_FIELD` (856) : générer de vrais **structs par overlay** (ov003, ov123 d'abord) à partir des offsets accédés sur une même base (pointeur `this`, globals). Un header `ov123_types.h` partagé règle des centaines de drafts d'un coup → relancer `fixall.sh` + `fj.py`.
- locaux `sp..`/unksp (436) : déclarer des tableaux/structs locaux de la bonne taille (spsize.py étendu aux drafts qui ne compilent pas).
- `goto` (321) : règle hunt `do-while/for` à appliquer avant compilation.
- `SECOND_REG` (58) : retour s64 (règle `second-reg s64`) ou hooks profile (B).
Ordre : ov123 (1350 f.) puis ov003 (1102 f.) — ce sont des C++ avec vtables : un `typedef struct VT {...}` par classe (vcall.py) + `this` typé.

### D. Les 1053 "size" (17 %)
1. Re-juger tout avec **tous** les profils : `AUTO_EXTRA_PROFILES='1.2/sp3,1.2/sp3 -profile,2.0/sp1p5 -profile'` + optsweep -O2/-O3 (session 7c : +106 rien qu'avec 1.2/sp3).
2. `mdiff.py` (WB_FULL=1) groupé par signature (`nearsig.py`) : les familles ov055–081 (~1000 B, copies de struct locales de 28 octets) → struct assign.
3. Ensuite transplantation `sibs`.

### E. Les 598 "near" (7 %, mais 231 à ≤ 4 diffs)
- Agents Sonnet en parallèle, protocole session 11 (juge seulement, écrit `build/hunt/agents/NAME.c`, jamais le ledger).
- Règles qui marchent : u8* au lieu de pointeur typé (~40 %), extern u8, `for+break`, temp pour résultat d'appel, retour anticipé, param inutilisé, champ → local avant cmp.
- Énigmes connues non résolues (ne pas y passer de temps) : ordre `moveq/movne`, `mov r0,r5` avant `bne` (ov107 twins), constant-store order `mov r1,#N` avant ldr pool (ov019/021/031/032).

### F. Ce qui n'est pas matchable en C (à sortir du compteur ou faire en asm)
- **ITCM 273 fonctions (25 KB)** : décodeur JPEG écrit à la main (r8–r10 globaux) + thunks `push {fp,ip}` → asm, refusé par la politique du workbench. Décider : soit fichiers `.s` "asm légitime" (comme les stubs BIOS), soit laisser.
- soft-float `_dadd/_dsub/_ddiv`, qsort (`swp`), fragments C++ EH, `__FindExceptionTable` (droppé à chaque verify) : asm.
- 10 stubs thumb non alignés 4 (Div, Mod…) : nécessitent de fusionner les voisins dans un même fichier.
- Thunks this-adjust `ldr ip,=0xfffffffc; add r0,r0,ip; b` : générés par mwcc pour l'héritage multiple → essayer une vraie classe C++ avec 2 bases et une méthode virtuelle surchargée (compiler en `.cpp`), pas du C.
- ~1 % du code : à accepter comme asm.

### G. Main (174 f., 86 KB) — SDK/MSL
Pas de donneur public (ntrtwl = leak, interdit). Regalloc bloquant (permrand inutile). Faible priorité : 5 % du code.
